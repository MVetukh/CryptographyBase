# CryptographyBase — Документация модуля `math.py`

> **Примечание (общая):** код и описанные функции предназначены для обучения и воспроизведения алгоритмов. Они **не предназначены** для продакшн-использования в криптографически чувствительных приложениях без дополнительных мер: использовать криптографически безопасный источник случайных чисел (`secrets`, `os.urandom` или библиотеки `cryptography`/`PyCryptodome`), а также учитывать, что чисто-Python реализации не дают защиты от побочных каналов (timing/power).

## `gcd(a, b)`

### Математическое описание

Наибольший общий делитель (НОД) целых чисел (a) и (b) — максимальное положительное целое (d), такое что (d \mid a) и (d \mid b). Алгоритм Евклида вычисляет (\gcd(a,b)) итеративно:
[
\gcd(a,b) = \gcd(b, a \bmod b)
]
с завершением, когда остаток равен 0.

### API

```py
gcd(a: int, b: int) -> int
```

**Аргументы**

* `a`, `b` — целые числа.

**Возвращает**

* `int` — (\gcd(a,b)), всегда неотрицательный.

**Исключения**

* `ValueError`, если `a == 0 and b == 0` (в реализации поднимается).

### Пример

```py
>>> from cryptobase.math import gcd
>>> gcd(48, 18)
6
>>> gcd(-8, 12)
4
```

### Ограничения / замечания

* Работает для произвольных целых, но при обоих нулях значение не определено (реализация бросает `ValueError`).
* Алгоритм эффективен (логарифмическое число шагов), пригоден для больших целых, но при экстремально больших размерах целесообразно использовать библиотеки на C (например `math.gcd` или GMP).

## `extended_gcd(a, b)`

### Математическое описание

Расширенный алгоритм Евклида находит числа (x, y) и (g = \gcd(a,b)) такие, что
[
a x + b y = g.
]
Эти коэффициенты называют коэффициентами Безу.

### API

```py
extended_gcd(a: int, b: int) -> tuple[int, int, int]
```

**Аргументы**

* `a`, `b` — целые числа.

**Возвращает**

* `(x, y, g)` — кортеж, где `g = gcd(|a|,|b|)`, и `a*x + b*y == g`.

**Исключения**

* `ValueError` если `a == 0 and b == 0`.

### Пример

```py
>>> extended_gcd(30, 12)
(-1, 3, 6)
# Проверка: 30*(-1) + 12*3 = -30 + 36 = 6
```

### Ограничения / замечания

* Обратите внимание на порядок возвращаемых значений (в этой реализации `(x, y, gcd)`), это не всегда совпадает с другими библиотеками, где часто возвращают `(g, x, y)`. Документируйте это при использовании.
* Для криптографии коэффициенты полезны при вычислении обратных по модулю и решении диофантовых уравнений.
* Реализация не constant-time — не подходит для секретных дел, если коэффициенты хранятся/используются в атакуемой среде.

## `mod_inverse(a, modulus)`

### Математическое описание

Ищется (a^{-1}) мод (m) — элемент (x) такой, что
[
a x \equiv 1 \pmod m.
]
Обратный элемент существует тогда и только тогда, когда (\gcd(a,m) = 1). Используется расширенный алгоритм Евклида.

### API

```py
mod_inverse(a: int, modulus: int) -> int
```

**Аргументы**

* `a` — целое число (может быть отрицательным; нормализуется к классу вычетов).
* `modulus` — целое > 1.

**Возвращает**

* `int` — обратный элемент (a^{-1} \bmod modulus) в диапазоне ([0, modulus-1]).

**Исключения**

* `TypeError` если аргументы не целые.
* `ValueError` если `modulus <= 1`, или если обратный элемент не существует (`gcd(a, modulus) != 1`).

### Пример

```py
>>> mod_inverse(3, 11)
4
# Проверка: 3*4 % 11 == 1
```

### Ограничения / замечания

* Для больших модулей лучше использовать проверенные реализации (например `Crypto.Util.number.inverse` из PyCryptodome) с оптимизациями и, если нужно, защитой от побочных каналов.
* В текущей реализации результат нормализуется в [0, m-1] и проверяется через `assert` — в production лучше выдавать контролируемое исключение при несоответствии, а не `assert`.

## `batch_mod_inverse(numbers, modulus)`

### Математическое описание

Вычисляет обратные для всех элементов списка ([a_1, a_2, ..., a_n]) по модулю (m) за время (\mathcal{O}(n + \log m)) путём использования префиксных произведений:
[
P_i = \prod_{j=1}^i a_j,\quad
P_n^{-1}\ \text{(по модулю $m$)} \Rightarrow
a_i^{-1} = P_{i-1} \cdot P_n^{-1} \cdot \prod_{j=i+1}^n a_j
]
реализовано через обратный проход с суффиксным произведением.

### API

```py
batch_mod_inverse(numbers: list[int], modulus: int) -> list[int]
```

**Аргументы**

* `numbers` — список целых чисел (ожидается, что каждый элемент взаимно обратим по модулю).
* `modulus` — целое > 1.

**Возвращает**

* `list[int]` — список обратных элементов в том же порядке.

**Исключения / поведение**

* Если `numbers` пуст, возвращается пустой список.
* Текущая реализация **неявно** предполагает обратимость всех чисел; если есть элемент, не обратимый, алгоритм сломается (рекомендуется добавить явную проверку и бросать `ValueError`).

### Пример

```py
>>> batch_mod_inverse([3,5,7], 11)
[4, 9, 8]
# Проверки: 3*4%11==1, 5*9%11==1, 7*8%11==1
```

### Ограничения / замечания

* Все элементы должны быть взаимно обратимы по модулю. Добавьте проверку `gcd(num, modulus) == 1` для каждого `num` если нужна строгая обработка ошибок.
* Полезно при создании обратных для векторных операций (например для Lagrange interpolation в полях) и экономит время по сравнению с вычислением обратного для каждого элемента отдельно.
* Производительность и корректность зависят от корректности `mod_inverse`.

## `solve_linear_congruence(a, b, modulus)`

### Математическое описание

Решает сравнение
[
a x \equiv b \pmod m
]
Общее решение существует тогда и только тогда, когда (d = \gcd(a,m)) делит (b). Если так, то уравнение сводится к
[
a' x \equiv b' \pmod{m'}
]
где (a' = a/d), (b' = b/d), (m' = m/d), и даёт ровно (d) классов решений в ([0,m-1]):
[
x = x_0 + k m',\quad k=0,\dots,d-1.
]

### API

```py
solve_linear_congruence(a: int, b: int, modulus: int) -> list[int]
```

**Аргументы**

* `a, b, modulus` — целые (`modulus > 1` ожидается).

**Возвращает**

* `list[int]` — список всех решений в диапазоне ([0, modulus-1]). Если решений нет — пустой список.

**Исключения**

* `TypeError` если аргументы не целые.
* `ValueError` если `modulus <= 1`.

### Пример

```py
# Решаем 4*x ≡ 6 (mod 10)
>>> solve_linear_congruence(4, 6, 10)
[4, 9]  # т.к. gcd(4,10)=2, решений 2: x≡4, x≡9 (mod 10)
```

### Ограничения / замечания

* Возвращаемые решения в canonical форме в [0,m-1].
* Функция корректно обрабатывает случаи `a == 0` и `a == 1`.
* Работает для любых целых modulus > 1; но для больших modulus и/или при повторных решениях для множества модулей можно применять CRT.

## `solve_linear_congruence_system(equations)`

### Математическое описание

Решает систему линейных сравнений вида (a_i x \equiv b_i \pmod{m_i}). Для сводимых к простому виду и применимых CRT, сначала требуется, чтобы окончательные модули (m_i) были попарно взаимно простыми — тогда решение находится единственным по модулю (M = \prod m_i) методом китайской теоремы об остатках (CRT):

Для каждого i:

* найти решение (x_i) сравнения (a_i x \equiv b_i \pmod{m_i}),
* затем собрать единое (x) по CRT:
  [
  x \equiv \sum_i x_i M_i y_i \pmod M,\quad M_i = M/m_i,\ y_i = M_i^{-1} \bmod m_i.
  ]

### API

```py
solve_linear_congruence_system(equations: list[tuple[int, int, int]]) -> list[int]
```

**Аргументы**

* `equations` — список троек `(a, b, m)`.

**Возвращает**

* `list[int]` — либо пустой список (если система несовместима), либо список с единственным решением `[x]` в модуле `M = ∏ m_i`.

**Исключения**

* `ValueError` если модули не попарно взаимно просты.

### Пример

```py
# Решаем систему:
# x ≡ 2 (mod 3)  (получаем как a=1, b=2, m=3)
# x ≡ 3 (mod 5)
>>> solve_linear_congruence_system([(1,2,3), (1,3,5)])
[8]  # 8 ≡ 2 mod 3, 8 ≡ 3 mod 5
```

### Ограничения / замечания

* В текущей реализации **требуется** взаимная простота модулей — это отражено в документе. В общем случае (когда модули не взаимно простые) требуется более общая логика CRT и проверка согласованности по `gcd(m_i, m_j)`.
* Функция возвращает только одно представление решения (минимальное nonnegative).

## `miller_rabin_test(n, k=None, /, bases=None)`

### Математическое описание

Тест Миллера–Рабина — вероятностный тест на простоту числа (n). Представление (n-1 = 2^s d) с нечётным (d). Для случайной базы (a \in [2, n-2]) вычисляют:
[
x = a^d \bmod n
]
и проверяют, является ли (x) тривиальным свидетелем простоты ((x \equiv 1 \pmod n) или (x \equiv -1 \pmod n)), либо при последовательных возведениях в квадрат становится (-1). Если база (a) обнаруживает составность — (n) составное. После (k) независимых раундов вероятность ошибочного признания составного числа простым ≤ (4^{-k}).

Также существует набор фиксированных баз, делающих тест детерминированным для (n < 2^{64}).

### API

```py
miller_rabin_test(n: int, k: Optional[int] = None, /, bases: Optional[list[int]] = None) -> bool
```

**Аргументы**

* `n` — целое > 1.
* `k` — число раундов (если `None`, выбирается по размеру `n`).
* `bases` — явный список оснований; если указан, тест работает детерминированно для соответствующих диапазонов.

**Возвращает**

* `True` если `n` вероятно простое.
* `False` если `n` доказано составное (найден свидетель).

**Исключения**

* `TypeError` при недопустимом типе.
* `ValueError` для некоторых некорректных входов (реализация может бросать для `n ≤ 3` — рекомендуется поправить так, чтобы `2` и `3` возвращали `True`).

### Пример

```py
>>> miller_rabin_test(2**127 - 1, k=20)
True  # скорее всего простое (Mersenne candidate), но реальная проверка требует дополнительных шагов
```

### Ограничения / замечания

* Это **вероятностный** тест (если не заданы специальные базы); для абсолютной гарантии для больших чисел нужен детерминированный алгоритм/доказательство.
* Для генерации криптопримитивов обычно ставят `k = 40..100` для высокой уверенности.
* В реализации важно использовать крипто-стойкие случайные основания (`secrets`), а не `random`.
* Для малых `n` реализованы оптимизации (trial division), а для `n < 2^64` можно использовать детерминированный набор баз (реализовано в отдельной функции).

## `miller_rabin_deterministic_small(n)`

### Математическое описание

Использует предвыбранные множества оснований, позволяющие сделать тест Миллера–Рабина детерминированным для чисел (n < 2^{64}). Известны таблицы оснований, дающие гарантию правильного результата на заданных диапазонах.

### API

```py
miller_rabin_deterministic_small(n: int) -> bool
```

**Аргументы**

* `n` — целое (ожидается (n < 2^{64}) для корректной детерминации).

**Возвращает**

* `True` если `n` простое, `False` если составное.

### Пример

```py
>>> miller_rabin_deterministic_small(2_152_302_898_747)
True  # если число попадает в диапазон и набор баз покрывает его
```

### Ограничения / замечания

* Если `n >= 2^{64}` — функция не гарантирует детерминированный результат и в реализации может возбуждать `ValueError` при использовании в `is_prime(method="deterministic")`.
* Для больших чисел используйте вероятностные тесты с большим числом раундов или другие методы.

## `generate_probable_prime(bit_length, k=100)`

### Математическое описание

Создаёт `candidate` путём генерации случайного нечётного числа заданной битовой длины и проверяет его на простоту тестом Миллера–Рабина с `k` раундами. Возвращает первое прошедшее испытание — вероятно простое число.

### API

```py
generate_probable_prime(bit_length: int, k: int = 100) -> int
```

**Аргументы**

* `bit_length` — требуемая битовая длина (>= 2).
* `k` — число раундов Миллера–Рабина (по умолчанию 100).

**Возвращает**

* `int` — вероятно простое число заданной длины.

**Исключения**

* `ValueError` если `bit_length < 2`.

### Пример

```py
>>> p = generate_probable_prime(16, k=20)
>>> p.bit_length()
16
>>> is_prime(p)  # вероятно True
True
```

### Ограничения / замечания

* В текущей реализации используется модуль `random` для генерации кандидатов. Для криптографических нужд **обязательно** заменить генератор на крипто-стойкий (`secrets.randbits`) или использовать `Crypto.Util.number.getPrime`.
* Генерация больших (2048+, 4096) битовых простых чисел на чистом Python будет медленной; для практической генерации ключей используйте оптимизированные реализации.

## `is_prime(n, method="auto")`

### Математическое описание

Универсальная обёртка для проверки простоты числа. Выбирает подходящий метод в зависимости от размера `n`:

* trial division для маленьких (n),
* детерминированный набор баз для (n < 2^{64}),
* вероятностный Миллер–Рабин для больших чисел.

### API

```py
is_prime(n: int, method: str = "auto") -> bool
```

**Аргументы**

* `n` — целое число.
* `method` — `"auto"`, `"miller-rabin"`, `"deterministic"`, `"trial-division"`.

**Возвращает**

* `bool` — True если `n` (вероятно) простое.

### Пример

```py
>>> is_prime(7919)
True
>>> is_prime(15)
False
```

### Ограничения / замечания

* Для `method="deterministic"` поддерживается только `n < 2^64`.
* Для больших `n` возвращаемое значение в `auto` — вероятностное и зависит от параметров MR.
* Для гарантии простоты используйте дополнительные проверки/простые доказательства (например, APR-CL или использование специализированных библиотек).

## Общие замечания по модулю `math.py`

### Безопасность RNG

* **Немедленно** заменить все использования `random` в коде, если планируешь генерировать ключи/простые числа для криптографии. Вместо `random.getrandbits`/`random.randint` использовать `secrets.randbits` / `secrets.randbelow` или `Crypto.Random.get_random_bytes`.

### Constant-time и SCA

* Python-реализации не являются constant-time и могут быть уязвимы к побочным каналам. Для критических операций используйте библиотеки на C, которые реализуют защиту от SCA (например, libsodium, OpenSSL с соответствующими настройками).

### Тесты

* Рекомендую написать unit-tests и property-tests (Hypothesis) для каждой функции (особенно для `extended_gcd`, `mod_inverse`, `batch_mod_inverse` и `solve_linear_congruence`).

### Производительность

* Для больших ключей (2048 бит и более) используйте проверенные библиотеки (GMP, PyCryptodome, PyCA). Чистый Python будет медленным.
